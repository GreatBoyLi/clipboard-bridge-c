# 菜单栏、托盘与主机选择 Mac

此版本为一台 Windows 保存多台 Mac 的配对，但同一时刻只允许所选 Mac 使用 Clipboard Bridge。Mac A 的剪贴板不会主动同步给 Mac B。Moonlight 的串流连接仍自行管理，Windows 托盘的选择只控制本程序。

## 编译与启动

先停止两端旧终端程序，等待 Windows 滚动守护程序恢复设置。此版本不添加开机/登录自动启动。

- Mac：`bash scripts/build_mac.sh`，然后双击 `build/Clipboard Bridge.app`。菜单栏出现 **CB** 图标，无 Dock 图标、终端窗口。完整 `.app` 可移到「应用程序」，不要拆开内部文件。
- Windows：在 Visual Studio x64 Native Tools Command Prompt 运行 `scripts\build_windows.bat`。然后双击 `build\clipboard-bridge-tray.exe`，点击系统托盘图标（可能在隐藏图标中）。它必须与 `clipboard-bridge.exe` 保持在同一文件夹。使用静态运行库，无需终端保持运行。

Mac 已配置后，每次手动打开应用会尝试连接；Windows 手动打开托盘程序后恢复上次所选设备。这不等于随系统启动。保留原来的 CLI 使用方式，但同一台机器不要同时运行 GUI 与旧 CLI。

## 首次配对

1. Windows 首次启动，在「连接设置」填写 **本机** Tailscale IPv4，当前主机是 `100.87.202.121`，端口默认 `47321`，滚动行数同步默认开启。不能填写 `0.0.0.0`。
2. 托盘选择「添加 Mac」，填写能区分设备的名称。
3. 选择生成独立密钥，并导出为 `.key` 文件；仅交给对应 Mac。已有当前 Mac 的旧密钥可选择导入，避免重新生成；另一台 Mac 必须使用不同密钥。
4. 对应 Mac 在 CB 菜单 →「主机与配对」填写 Windows 地址 `100.87.202.121` 和端口，选择「导入配对密钥」，导入第 3 步的文件。
5. Windows 选中这台 Mac。Mac 会连接/自动重试，认证成功后显示「已连接」。重新复制一次文字、图片或文件才会开始同步。

添加第二台 Mac 时重复步骤 2–4。每台密钥独立，Windows 拒绝重复凭据。导出的密钥用于配对，不要放进公开 Git 仓库或交给别的设备。

## 切换、暂停与退出

Windows 托盘中点击设备名称选择允许连接的 Mac。程序先请求旧同步进程正常退出，取消未完成的传输、释放输入状态、恢复滚动行数，再启动新凭据的监听。过程中会显示断开/恢复状态；网络操作可能等待数秒，界面继续响应。桌面版本会等待滚动守护进程真正完成恢复；恢复失败时暂停并阻止自动切换，检查后可明确重试。其他 Mac 等待主机选择或重连。

Windows 有暂停/恢复和移除设备功能；移除后需要重新配对。Mac 可连接/断开，并分别开启键盘映射、Caps Lock、三指导航与两指行数控制，修改后会正常重启同步会话。后三项依赖键盘映射启用。

从菜单中退出时会关闭后台同步进程；界面意外退出时，控制管道断开也会让同步进程走清理流程。旧会话的剪贴板不在切换/重连时主动发送，重新复制才同步。

## Mac 输入权限

从终端改为 `.app` 后，应给 **Clipboard Bridge** 授予辅助功能权限，而不仅是终端。CB 菜单「输入权限设置」可触发系统授权提示。Caps Lock 底层输入按系统提示授予输入监控权限。授权后先断开再连接；仅剪贴板同步可关闭键盘映射。

构建脚本默认本地 ad-hoc 签名；可通过 `CB_SIGN_IDENTITY` 指定已有签名身份。重新编译或移动应用后如果系统再次要求授权，按系统提示重新授权。

## 配置位置与状态

- Mac 主机/开关配置：NSUserDefaults 域 `net.greatboyli.clipboardbridge`；应用内部配对密钥 `~/.config/clipboard-bridge/menu-pairing.key`。原 CLI 的 `pairing.key` 保留。
- Windows：`%LOCALAPPDATA%\ClipboardBridge`，保存设备列表、连接设置与各设备独立密钥，仅当前用户与系统可访问。
- Mac 菜单显示连接状态，「查看连接信息」显示最近日志；Windows 托盘菜单/悬停显示所选设备和状态。日志不显示剪贴板内容或密钥。
- 文件缓存自动清理规则不变，参见 [文件同步](files.md)。

## 验证范围

`bash scripts/test_desktop_mac.sh` 验证凭据校验、退出管道、真实 loopback 身份选择、会话基线与清理；测试不接触用户剪贴板或按键。Mac 构建包含菜单栏与 `.app` 签名检查。Windows 构建脚本包含凭据和控制管道测试；Windows 托盘的原生编译、实际配对和滚动恢复仍需在 Windows 验收。
