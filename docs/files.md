# 文件与文件夹双向同步

更新两端源码、停止旧程序后重新编译：Mac `bash scripts/build_mac.sh`；Windows `scripts\build_windows.bat`。启动命令及配对密钥保持原样，文件同步默认启用。Caps Lock 映射仍需保留 `CB_CAPS_KEY=1`。

在 Finder 或 Windows 文件资源管理器选中文件或文件夹并复制，等待终端显示 `Files verified and clipboard ready for paste.`（接收端）或 `Remote clipboard update confirmed.`（发送端），再在另一端的目标文件夹粘贴。Mac 端 ⌘V 的已有映射会等待正在发送的文件完成；在接收端手动粘贴前请等待完成提示。

支持单个/多个普通文件和文件夹，可以混合选择，保留完整目录层级、空文件和空文件夹，包括中文与 Emoji 名称。单次最多 64 个顶层项目，展开后最多 1024 个文件/目录条目、32 层，文件总大小最多 1 GiB；相对路径最长 1024 个 UTF-8 字节，清单最多 256 KiB。子目录中可以有同名文件，不同顶层项目的同名或同一目录内的大小写冲突会拒绝。

不跟随符号链接和 Windows junction/重解析点，不支持云端虚拟附件、剪切或跨平台文件属性复制。目录中存在这些链接或不兼容 Windows 的名称时，整次复制会拒绝。复制期间源文件或目录结构改变会取消同步。

两端都需更新并重新编译，才能复制文件夹；普通文件仍保留原清单格式。剪贴板仅放入所选顶层项目，不会把子文件拆成独立粘贴项。

文件按 16 KiB 分块传输，内存不会随着整个文件大小增长。完成时检查总长度和逐文件 CRC32，只在全部通过后写入文件剪贴板；日志按进度显示，不打印文件名或内容。网络断开/接收失败时清理尚未完成的文件，不在重连后补发旧复制。

接收的文件位于系统临时目录内的独立 `clipboard-bridge-*` 子目录。成功接收后会保留，以便程序退出后仍可粘贴；粘贴到目标位置会产生独立副本。已经不需要的接收临时目录可以手动删除（删除前请先粘贴或复制新的内容，剪贴板仍可能引用这些文件）。

仅运行新增路径和受影响接口的必要测试：Mac `bash scripts/test_files_mac.sh`。测试使用私有临时目录、独立测试剪贴板和本地模拟会话。Windows 构建脚本包含文件/目录流和原生 CF_HDROP 内存转换测试，不操作系统剪贴板。Windows 原生构建和实际文件资源管理器粘贴需在 Windows 验证。
